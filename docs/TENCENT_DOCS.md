# 腾讯文档：官方 MCP 读写

插件负责本人授权和修改确认。AI 在 DSH 会话使用[腾讯官方 MCP](https://developer.cloud.tencent.com.cn/mcp/server/11803)，端点为 `https://docs.qq.com/openapi/mcp`。文档原版式和编辑器使用[腾讯文档官网](https://docs.qq.com/desktop/)。

## 连接自己的账号

1. 打开 DSH 的“腾讯文档”，点击“登录并授权”。
2. 点击“在浏览器确认授权”，在腾讯官方页面登录本人账号并确认授权；无需把密码、验证码或 Token 发给 AI。
3. 回 DSH 刷新状态，点击“检查连接”。看到“已授权”表示凭据已保存，发现工具表示 MCP 已连接；仍需实际读取自己的文档验证业务权限。

原有本机授权继续使用，支持 OAuth 自动刷新。也可在折叠的“使用个人 Token”中录入本人从腾讯获得的 Token；保存到宿主凭据库，不写入公共配置。OAuth 回调仅监听本机 `127.0.0.1:43189`，使用 PKCE 和 state 校验。重新授权或断开会关闭修改建议，并使旧的待确认提案失效。

## 在会话中使用

将自己的文档链接贴进 DSH 会话，明确要求读取或修改，例如：

> 读取这个腾讯文档链接，总结本周进展，只读，不做改动。

> 读取这个腾讯表格的工作表和 A1:C10 范围，保留行列关系，告诉我哪些事项已完成。

> 将指定单元格改为“完成”，先生成具体修改建议，等待我确认。

官方工具会作为 `mcp__tencent_docs__…` 注册给 AI，保持原有工具名映射。无需再在 MCP 管理中添加另一份可直接写入的腾讯服务。模型对工具调用的支持、腾讯账号权限、额度和文档类型都会影响结果。可在插件的折叠区域执行一次不调用模型的文档只读检查。

## 修改前确认

默认关闭“允许 AI 提出修改建议”。开启只允许生成提案，每一项仍须在插件“待确认修改”中点击“审阅修改”，核对工具、目标文档和完整参数，再点击“确认写入腾讯文档”。拒绝不会写入；确认只执行对应 ID 的原始参数，模型不能替换确认参数或自行批准。

对有明确文档 ID 的现有文档，生成提案时先读取原内容，确认时重新读取并核对；单元格设置还核对具体范围。文档已变化、权限关闭、提案被拒绝或账号变化时，尚未发出的写入会停止。删除工具不向 AI 注册。新/不明确的工具默认需确认，不能单靠服务端的只读标签绕过检查。

工具实际返回成功后记录“已执行”；需要让 AI 通过官方只读工具读回核对，不能把提案当作修改完成。网络中断或进程关闭导致结果不明确时显示“结果待核对”，先在官网/只读工具检查，不自动重试，避免重复创建或写入。

## 简化后的边界与保留

- 不再复刻文档列表、表格网格、PPT、图片预览或网页选区；不安装独立浏览器，也不嵌入跨域登录页。
- 腾讯官网负责显示和手动编辑。AI 只能读取官方 MCP 确实返回的内容，不承诺能获取图片对象、PPT 版式或官网上的全部内容。
- 更新保留原有 OAuth、提案记录、旧浏览器和 `storages/tencent_docs/web-inbox` 本机数据；不会自动迁移、删除或发送旧接收内容。旧浏览器不再与新版插件接通。
- 安装采用 Desktop 原生 generation；资料库等其他插件独立开发时，使用 `--only @local/dsh-tencent-docs`，空闲后由本人重启加载。
- 自动化测试与真实账号/界面验收分别记录，见[验证记录](VERIFICATION.md)和[验收清单](ACCEPTANCE.md)。
